# 1단계에서 확인한 것

구현하며 실측으로 확인한 사실과, 다음 단계로 넘기는 항목만 적는다.

## Supabase 플랫폼 사실 (전부 실측 확인)

- **새로 만든 뷰에도 `anon`·`authenticated` 에 ALL 권한이 기본으로 붙는다.** Supabase 의 `ALTER DEFAULT PRIVILEGES ... GRANT ALL ON TABLES` 가 뷰를 포함하기 때문이다. 소유자 권한 뷰(= `security_invoker` 를 끈 뷰)는 밑단 테이블의 RLS 를 우회하므로, 쓰기 권한이 남아 있으면 RLS 가 있으나 마나다. 1단계에서 `menus_public_v2` 가 정확히 이 상태였고 anon 이 메뉴 전체를 지울 수 있었다(`0007_view_grants.sql` 로 회수).
  → **규칙: 새 뷰를 만들 때마다 `revoke all` 후 필요한 권한만 `grant`.** 3단계의 마을원 명단 마스킹 뷰는 생년월일·휴대폰번호 위에 만들어진다.
- **새로 만든 함수에도 `PUBLIC`·`anon`·`authenticated` 에 EXECUTE 가 기본으로 붙는다.** `revoke ... from public` 만으로는 회수되지 않는다. 내부 전용 함수는 세 대상 모두에서 회수해야 한다(`cafe_is_open` 사례).
- **`postgres_changes` 는 RLS 를 따른다.** select 정책이 없는 역할은 이벤트를 하나도 받지 못한다. 게스트용 실시간은 1단계에서 동작하지 않으며, 2단계에서 로그인 사용자에게 정책이 생기면 그때부터 동작한다. 대조군(anon 이 읽을 수 있는 테이블)으로 장치 이상이 아님을 확인했다.
- **DELETE 이벤트는 RLS 필터를 거치지 않는다.** `relreplident` 가 `d` 라 구독자는 지워진 행의 PK 를 받는다. 1단계에는 주문 항목을 지우는 경로가 없다(취소는 UPDATE). 4단계 운영 화면이 처음으로 삭제를 하게 되므로 그때 확인할 것.
- `npx supabase` 는 이 환경에서 멈춘다. 전역 설치된 `supabase` 를 쓴다.

## 테스트에서 배운 것

- **부정형 보안 테스트는 "빈 테이블이라 0행"과 "정책이 막아서 0행"을 구분해야 한다.** 실제 행을 넣고 확인하지 않으면 정책을 지워도 통과한다(1단계에서 두 번 발생).
- **읽기만 검사하는 RLS 테스트는 쓰기 구멍을 못 잡는다.** 뷰의 쓰기 권한 문제가 15번의 리뷰를 통과한 원인이다. 새 정책·새 뷰마다 읽기와 쓰기를 모두 시도하고, 실패뿐 아니라 **데이터가 그대로인지** 확인한다.
- **DB 테스트는 공유 상태를 원복해야 한다.** `supabase db reset` 은 스위트당 한 번만 돌고 vitest 는 파일 경로 순으로 실행한다. `cafe_settings_v2` 를 바꾸는 파일은 `afterEach` 에서 되돌린다. 정리 코드는 단언 뒤가 아니라 `try/finally` 에 둔다.

## 2단계로 넘기는 항목

- 로그인 사용자가 게스트 토큰을 넘기는 경로에 테스트가 없다. 인증 세션 픽스처를 처음 만드는 태스크가 회귀 테스트를 추가한다. 함께: `cancel_order_item` 의 `or` 분기는 로그인 사용자가 게스트 토큰을 알면 그 항목을 취소할 수 있다 — `auth.uid()` 가 있으면 `p_guest_token` 을 무시하도록 좁힌다.
- 옵션 시트에 포커스 트랩·초기 포커스·포커스 복원이 없다. `aria-modal="true"` 가 배경이 비활성이라고 알리지만 실제로는 아니다.
- 에러 바운더리가 없다. `menus_v2.options.temperature` 가 비면 화면 전체가 죽는다 — 4단계 메뉴 편집기가 그 상황을 만들 수 있다.
- `supabase gen types typescript` 로 DB 타입을 생성하면 `api.ts` 의 `as` 캐스트와 스키마 드리프트 문제가 함께 닫힌다.
- 하단 탭에 `env(safe-area-inset-bottom)` 미적용(코드베이스 전체가 미적용이라 한 번에 함께 넣는다).

## 미해결 제품 결정

- **게스트 토큰이 `localStorage` 에 있다.** 요구사항은 "브라우저 세션이 유지되는 동안"이라 하는데 `localStorage` 는 그보다 넓다. 폰을 빌려준 경우 빌린 사람이 그날 남은 시간 동안 주인의 주문을 보고 취소할 수 있다(날짜 범위로 하루에 묶이긴 한다). `sessionStorage` 로 바꾸면 스펙과 화면 문구에 더 맞는다.
- **카테고리를 커피·논커피·음료로 했다.** 요구사항은 커피·차·음료라고 적었다. 실제 메뉴판이 COFFEE / NON COFFEE / COLD DRINKS 로 묶여 있고 라떼류가 "차"에 들어가지 않아 메뉴판을 따랐다. enum 이 DB 에 박혀 있어 나중에 바꾸면 마이그레이션이 필요하다.
